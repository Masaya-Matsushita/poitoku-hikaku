# 00 — ビジョンと成功の定義

## プロジェクト名

ポイ得比較（poitoku-hikaku）

## 一言で

ポイントサイトの案件を横断比較し、価格履歴と「今が買い時」判定を提供するWebサービス。
開発・運用はAI主導で行い、人間（オーナー）は方針決定とレビューに専念する。

## 目的（優先順）

| 優先 | 目的 | 成功の定義 |
|---|---|---|
| 1 | **最先端のAI主導開発手法の実践** | クラウド上で夜間に改修・デプロイが走り、KPIを見て自律的に改善するループが3ヶ月以上稼働している |
| 2 | 副収入源の柱を作る | 紹介報酬＋案件報酬で月数万円。ただし**初期リリースの成功条件には含めない** |

目的1が満たされれば、目的2が未達でもプロジェクトは成功と定義する。
これは2026年2月の一時停止（集客の壁）を踏まえた意図的な設計である。

## 非目標（やらないこと）

- どこ得？を対応サイト数で上回ること
- 記事執筆・SNS運用など、人間の継続労力を前提とした集客
- 月額コストの発生（ドメイン代を除き **月0円** を厳守。詳細は ADR-0002）
- 有料LLM APIの日次運用（詳細は ADR-0003）

## ポートフォリオの第一弾として

本プロジェクトは、AI主導で0円運用のアプリを複数並行で走らせ、合計で月10万円規模の継続収益を目指す構想の**第一弾**である。
したがって以下を設計原則とする。

- **運用はAIなしで回る**：AI（Claude Code / Routine）に依存するのは開発と改善のみ。日次クロール・配信・DBは Max Plan の契約が切れても止まらない構成にする
- **再利用は2本目で抽出する**：1本目で共通基盤を作らない。持ち越し候補（リポジトリの型、0円インフラ構成、クロール→履歴→自動生成→検知のパイプライン）を意識してディレクトリを分けるに留める
- **学びは `docs/lessons.md` に残す**：何を作ったかより、何が想定と違ったかを記録し、第二弾のアイデア選定に使う

## 制約

- オーナーは本業のあるエンジニア。投入できるのはレビュー時間のみ（目安：平日30分、週末2時間）
- クロール対象サイトの robots.txt・利用規約を遵守する
- ステマ規制（景品表示法）に従い、紹介リンクを含むページには表示義務を果たす

## 半年前（2026-02）からの変更点

| 項目 | 2026-02 | 2026-09 |
|---|---|---|
| 開発主体 | 人間＋AI補助 | AI主導、人間はレビュー |
| 最重要要件 | メンテナンスを減らす | メンテナンスはAIがやる（要件が反転） |
| 抽出方式 | LLM抽出（Crawl4AI） | CSSセレクタ、生成・修復のみLLM |
| スタック | Next.js / Vercel / Supabase / Python | Go / React / Firebase Hosting / Supabase / GitHub Actions |
| 集客 | 未定 | プログラマティックSEO＋価格変動アラート |
| 成功条件 | 動く仕組み | 自律改善ループの稼働 |
