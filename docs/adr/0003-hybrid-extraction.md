# ADR-0003 抽出はCSSセレクタ、生成・修復のみLLM

日付：2026-09-07　ステータス：採択

## 背景

2026-02 は Crawl4AI + gpt-4o-mini による LLM 抽出を採用したが、20サイト規模で月数万円になる試算が出て停止した。
当時のセカンドオピニオンで「日次はCSSセレクタ、LLMはセレクタ生成と構造変化の検知に限定するハイブリッド」が提案されていた。

## 決定

```
日次クロール：CSSセレクタ（YAML定義）で抽出。LLM呼び出しゼロ
サイト追加時：Claude Code がページを読んでセレクタYAMLを書く
抽出失敗時：夜間 Routine が検知 → セレクタ再生成 → テスト → PR
```

## 理由

- 日次コストが0になる
- 半年前に「嫌だった」手動セレクタ修正が、今回は自律ループの最初の題材になる
- 有料LLM API・ローカルLLM（Ollama）の運用が不要になり、Macを開きっぱなしにする必要もない

## 検知の定義（初期値、運用しながら調整）

- 前日比で取得件数が 50% 未満
- 数値抽出失敗率が 5% 超
- 全件で同一の還元額（セレクタが別要素を掴んでいる兆候）

## 将来

案件名の正規化（サイト横断マッチング）のように LLM が本当に必要な処理が出た場合は、差分のみ処理する設計で別ADRを起こす。
