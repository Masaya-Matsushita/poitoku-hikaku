## 収益目標とマイルストーン

### 目標

| 段階 | 月間収益 | 備考 |
|------|---------|------|
| 現実的目標 | 月1〜3万円 | メンテ月1時間以下で達成できれば成功 |
| 理想目標 | 月10万円 | 5サイト以上、月間PV5万以上が条件 |

### 収益シミュレーション（参考）

```
【紹介報酬の構造】
・ハピタス: 300pt + 被紹介者の獲得ptの1-40%
・モッピー: 300P + 被紹介者の獲得ptの最大10%

【月10万円達成の目安】
・紹介登録: 月100人以上
・または累計500人以上の継続利用
・必要PV: 月5万以上
・必要サイト数: 5サイト以上
```

### MVP段階の期待値

- **収益期待: ゼロ**
- 2サイトのみではプロダクト価値がなく、収益化は不可能
- MVPは「仕組みの検証」が目的であり、収益化の検証ではない

## UI/UX改善（Phase 2以降）

### 紹介リンクの説明改善

**出典**: 最終確認MTG / ペルソナB（ライトユーザー）

**課題**:
初めてポイントサイトを使う人にとって、紹介リンクの意味が分かりにくい

**改善案**:
- 「紹介リンクから登録すると○○ポイントもらえます」のような具体的な説明を追加
- 各サイトの紹介特典を明示（ハピタス: 最大2,700pt、モッピー: 2,000P）

**優先度**: 中（Phase 2のUI実装時に対応）

## サイト拡張計画（MVP後）

### 拡張の必要性

- 2サイトのみでは競合（どこ得？等）に対する優位性がない
- 収益化には5サイト以上が必要
- ユーザー（特にコアユーザー）は5サイト以上でないと使わない

### 拡張優先順位

`docs/point-sites.md` に記載済み。以下は概要：

| 優先度 | サイト | 理由 |
|-------|--------|------|
| 1 | ポイントインカム | 大手、要調査 |
| 2 | ECナビ | 大手、要調査 |
| 3 | ちょびリッチ | 中堅、要調査 |
| 4 | ポイントタウン | GMO系、要調査 |

### 拡張時の作業

1. robots.txt確認
2. 利用規約確認
3. データ取得方法の調査（HTML埋め込みかJS動的ロードか）
4. ポイント単価の確認（円換算レート）
5. 紹介制度の調査・登録

## 技術的な検討事項

### GitHub Actions環境構築（Phase 3）

**課題**:
Crawl4AIはPlaywrightに依存している可能性がある。GitHub Actionsで動かす際の環境構築を検討する必要がある。

**対応方針**:
- PoCでローカル動作を確認
- Phase 3でGitHub Actions用のワークフローを構築
- 必要に応じてPlaywrightのセットアップステップを追加

### LLMコスト最適化（将来）

**現状**:
- gpt-4o-mini: 月$1-3程度（2サイト×100案件）

**検討オプション**:
- CSS抽出をメインにしてLLMはフォールバックのみ → 大幅削減
- ローカルLLM（Ollama等）を使う → $0（精度は要検証）

**対応時期**: コストが問題になった場合
